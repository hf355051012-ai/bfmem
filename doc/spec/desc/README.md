# 関数の記述の書き方(`doc/spec/desc/*.json`)

ソースファイル 1 つにつき JSON を 1 つ。`doc/spec/gen.py` がこれとソースから仕様書(`doc/spec/bfmem_spec.adoc`)と
図を作る。**宣言・引数の型・呼び出しの関係図はソースから自動で取り出す**ので、ここには書かない。

```json
{
  "file": "src/bfm_core.c",
  "summary": "このファイルの役割(章の冒頭に出る。AsciiDoc の段落)",
  "functions": [
    {
      "func": "bfm_init",
      "summary": "処理内容",
      "args": {"引数名": "意味", ...},        // ソースの引数の名前と順番に完全に合わせる。引数なしなら {}
      "ret": "戻り値",                         // void なら「なし」
      "pre": "前提条件",
      "notes": "注意事項",
      "flow": [ フローの手順, ... ],
      "indirect": ["関数名", ...],             // 省略可。関数ポインタ経由で呼ぶ関数(関係図に破線で足す)
      "entry_note": "OS からシグナルで呼ばれる" // 省略可。このソースの中に呼び出し元が無いときの説明
    }
  ]
}
```

- 文字列は AsciiDoc として表のセルに入る。コードの名前は `` `bfm_init()` `` のように逆引用符で囲む。
  箇条書きは `"* 1 つめ\n* 2 つめ"`。`|` は使わない(表が崩れる)。
- **書くのは事実だけ。** ソースに無い動きを推測で書かない。前提条件・注意事項は、ソースのコメントと
  呼び出し側の使い方から分かることを書く(無ければ「特になし」)。

## フローの手順

ソースの制御の構造(if・ループ・break・continue・goto・return)を **そのまま** 写す。文の 1 つ 1 つを箱にする
必要はないが、**分岐・繰り返し・抜け方・戻り値はすべて書く**。

| 手順 | 意味 | 図 |
|---|---|---|
| `{"do": "文"}` | 処理 | 四角 |
| `{"call": "func(...) を呼ぶ"}` | このプロジェクトの関数の呼び出しが主な処理 | 両側に線のある箱 |
| `{"if": "条件?", "then": [...], "else": [...]}` | 分岐。`then` が「はい」(下)、`else` が「いいえ」(右)。`else` は省略可。ラベルを変えるときは `"yes"` / `"no"` | ひし形 |
| `{"while": "条件?", "body": [...]}` | 先に条件を見る繰り返し(`while` / `for`)。条件が偽で抜ける | ひし形 |
| `{"loop": "説明", "body": [...]}` | 条件の無い繰り返し(`for (;;)` / `while (1)`)。`break` か `return` でしか抜けない | 六角形 |
| `{"dowhile": "条件?", "body": [...]}` | 後で条件を見る繰り返し | ひし形 |
| `{"switch": "式", "cases": [{"case": "値", "body": [...]}, {"default": true, "body": [...]}]}` | 多分岐。梯子の形に描く(case のひし形を縦に並べ、当てはまれば右へその処理、当てはまらなければ下の case へ。最後に default)| ひし形 |
| `{"return": "戻り値"}` | 戻る。`void` で値が無いときは `{"return": ""}` | 角の丸い箱 |
| `{"break": true}` / `{"continue": true}` | いちばん内側のループを抜ける / 次の繰り返しへ | 線 |
| `{"goto": "ラベル名"}` / `{"label": "ラベル名"}` | goto とその行き先 | 緑の楕円 |

- 関数の終わりまで落ちた場合は自動で「終了」を付ける。
- `else` の中身が `if` 1 つだけの連なり(`if … else if … else …`)も、switch と同じ梯子の形に描く(横に広がらないように)。
  三項演算子(`a ? b : c`)は、ソースで 1 つの文なら分岐にせず 1 つの箱に書く。
- 条件は `"rc != BFM_OK ?"` のようにソースの式でも、`"ポート層の初期化に失敗した?"` のように言葉でもよい。
  ただし **向き(はい・いいえ)をソースと合わせる**。
- `a && b` で途中の関数の呼び出しが分岐を作る場合(`if ((rc = f()) != OK || (rc = g()) != OK)`)は、
  呼び出しを順に分けて書く。

## 状態遷移図(`states`、省略可)

待たずに進める関数(呼ぶたびに先へ進み、待つところで `BFM_INPROGRESS` を返す状態機械)には、関数の記述に
`states` を足すと、フロー図の前に状態遷移図が入る(`images/state_*.drawio.svg`)。

```json
"states": {
  "start": "最初の呼び出し",                                   // 開始の箱(最初の状態へ線が 1 本)
  "list": [
    {"id": "H_START", "text": "説明"},                         // next を省くと list の次の状態へ 1 本
    {"id": "H_FW_WAIT1", "text": "説明", "wait": "待つもの"},  // wait があると黄色の箱と左の輪(BFM_INPROGRESS で留まる)
    {"id": "H_QUERY_ISSI", "text": "説明",
     "next": [{"to": "H_SET_ISSI", "label": "ISSI 1 に対応"}, {"to": "H_BOOT_QUERY", "label": "対応していない"}]},
    {"id": "H_DONE", "text": "済んだ", "next": [{"to": "END"}]}  // "END" は終わりの箱
  ],
  "end": "BFM_OK を返す",                                     // 終わりの箱
  "note": "失敗したとき…"                                      // 右上の注記(省略可)
}
```

- 状態は `list` の順に縦に並ぶ。すぐ下の状態への遷移はまっすぐ下へ、それ以外(飛ばす・戻る・終わりへ)は右の線で描く。
  自分へ戻る遷移(同じ状態の繰り返し)は線にせず、`text` か `wait` に書く。
- `id` はソースの enum の名前(ソースに名前が無ければ言葉でよい)。`--check` が調べるのは行き先の名前があるかだけ。
  **遷移がソースと合っているかは、人が突き合わせる。**

確かめ方(WSL):

```bash
python3 doc/spec/gen.py --list src/bfm_core.c   # ソースから取り出した関数・引数・呼び出し
python3 doc/spec/gen.py --check --partial       # 記述のあるファイルだけ検査
python3 doc/spec/gen.py --partial               # 記述のあるファイルだけで仕様書と図を作る
```
